## 2. 主实验：两种地图 × 三种控制条件

| 实验 ID | 地图版本 | 控制/学习条件 | 是否训练 | 核心问题 |
| --- | --- | --- | --- | --- |
| OLD_ZERO | MAP_OLD：冻结的原地图逻辑 | D2 控制链，四体 RL 残差为零 | 否 | 原地图的规划与控制参考表现 |
| NEW_ZERO | MAP_NEW：完成后的 coupled_search_v1 | 相同底层控制、安全与交接，四体 RL 残差为零 | 否 | 不依赖学习，新地图是否改善搜索与任务表现？ |
| OLD_B2 | MAP_OLD | 当前 D2+B2 repair-v2 | 是 | 原地图配原 B2 的完整系统 |
| NEW_B2 | MAP_NEW | 同样的 B2 算法与训练合同 | 是 | B2 不变时，更换地图是否改善完整系统？ |
| OLD_B3 | MAP_OLD | 当前 D2+B3 repair-v2 | 是 | 原地图配原 B3 的完整系统 |
| NEW_B3 | MAP_NEW | 同样的 B3 算法与训练合同 | 是 | B3 不变时，更换地图是否改善完整系统？ |

用户所说“新地图+D2”在这里表示保留 D2 的零残差控制与底层执行合同，使用新的上层搜索规划。新方案会改变搜索分配算法，因此运行结果必须标为 NEW_ZERO，保留独立 search_planner_id，不能重标为原始 D2。B2/B3 的学习身份也与地图身份分字段记录。

主报告首先给出三项配对比较：NEW_ZERO-OLD_ZERO、NEW_B2-OLD_B2、NEW_B3-OLD_B3。再分别在每个地图内比较 B2/B3 与 ZERO。后者检验该地图下 RL 的实际增益，不能事先假定加入 RL 一定更好。

## 3. 两类 RL 比较都保留，结论分开

### A. 各地图独立训练：主要系统实验

OLD_B2 / NEW_B2 分别在各自地图闭环中从新模型训练；OLD_B3 / NEW_B3 同理。对应种子使用相同初始权重生成规则和相同物理训练任务顺序，但模型、Replay、优化器状态、输出目录与最终检查点独立。

配对训练不能只设同一全局 seed 就认为输入完全相同：显式冻结每个训练 seed 的场景清单、回合顺序及环境 innovation seed。新地图内部的假设、候选和复核随机流另设独立生成器，不消耗场景/环境/Actor 探索噪声的随机流。训练中不得在两组间共享 Replay 或继续训练对方权重。

本比较衡量“新地图及其学习适应后的完整系统收益”。它不能单独证明固定策略下地图的直接贡献，故需要下面 B 类诊断。

### B. 同一冻结策略跨地图：归因诊断

每个最终策略固定 Actor、B3 编码器及其余已学习参数，不再更新，分别在 MAP_OLD 和 MAP_NEW 上评估。每对运行使用完全相同的权重哈希、测试场景与环境种子。记录 train_map 与 eval_map：

| 策略来源 | 原地图评估 | 新地图评估 |
| --- | --- | --- |
| OLD_B2 / OLD_B3 训练得到的策略 | 原生配置 | 跨地图诊断 |
| NEW_B2 / NEW_B3 训练得到的策略 | 跨地图诊断 | 原生配置 |

原生评估直接复用主实验结果；只补充另一地图的评估。跨地图性能也可能受训练分布变化影响，应分别报告两种策略来源，不能只挑有利的来源。

现有检查点严格绑定来源和配置，当前尚无合法的跨地图评估适配器。后续应在统一 Active 源版本下为两种地图建立显式诊断协议，保留原 checkpoint 身份，只把 eval_map 作为评估条件。不得关闭 require_source_match、篡改训练地图字段、重命名旧 checkpoint 或自动恢复历史模型来完成该比较。

## 4. 场景、种子和预算

以下预算现已写入 configs/map_comparison_v1.json，每个 RUN 在 prepare 时锁定；配置交付不构成自动执行授权：

| 层级 | 设计 |
| --- | --- |
| 机制检查 | 按 AGENTS.md 总预算：最多 8 回合 × 32 步；每个临时模型最多 4 次完整多智能体更新；纯数据检查优先 |
| 开发集 | 由 Active 独立生成并冻结 20 个开发场景，用于先验/预算/容差选择；不能作为未见测试集 |
| 主训练 | 首轮每模型 300 回合、每回合最多 400 步；其余学习参数不变 |
| 训练种子 | 首轮 2 个：2729、3729；用于预算受限的探索，后续确认实验另设预算 |
| 最终测试 | 冻结 100 个未参与训练、开发或选参的物理场景，六组使用同一有序清单 |
| 选检查点 | 最后一个完整训练回合的 checkpoint；不根据测试集分数选最优回合 |
| ZERO 随机性 | 没有训练种子。主要比较使用预先冻结的规划随机配置；额外规划随机种子作为嵌套敏感性诊断，不伪装成独立训练重复 |

训练、开发、测试按物理任务指纹及场景 seed 检查交集，不能靠重命名 scene_id 分离。训练场景清单与测试清单冻结后均保存哈希。旧目录中的历史 20 场景或汇总结果不导入 Active 作为本轮证据。

当前首轮预算为 4 个学习组 × 2 个 seed × 300 ep = 8 个模型、2400 个训练回合，上限 960,000 个训练环境步。0/50/.../300 ep 在独立的 12 场固定验证集评估，共 672 回合；最终 8 个模型与 2 个 ZERO 各测试 100 场，共 1000 回合。原 20 模型方案已归档。收敛筛查阈值、种子曲线、验证/测试隔离和 Linux diagnose 命令见 MAP_EXPERIMENT_LINUX_20261020_v1.md。两种子结果是初步证据，不能作为充分统计确认。

主训练先保留现有“同回合数、完成已开始回合”的行为。成功或碰撞会使实际步数和更新次数不同，因此不能称为等环境步或等墙钟。必须记录累计物理步、优化器更新数与墙钟，给出任务表现随环境步/时间的曲线。若再做严格等步数或等墙钟实验，应单独冻结预算和停止协议，不静默改变当前 Trainer。

## 5. 必须保持一致的条件

- 4 个智能体、28D 观测、3D 动作、124D Critic、gamma=.95、网络、优化器、原奖励/权重、Replay 和更新调度均保持原合同。
- 两地图共用动力学、真实目标/障碍过程、传感器、原发现判据、严格碰撞终止、最大步数、可靠交接与发现后冻结。
- B2 只与同一 B2 比地图差异，B3 只与同一 B3 比；B3 的公共联合上下文仍按现有接口构造和披露。
- 原公开建图与安全链保留，新地图只从合法公共证据构建私有研究估计器；不向 Actor 或新规划器泄漏隐藏目标/真实障碍。
- Executor 首版保持原待命、共享扫描和交接机制。新搜索路线可能间接改变其待命选择，需记录实际位置、行程和扫描贡献，不能声称两组 executor 轨迹完全相同。
- 所有输出新建目录；输入、地图版本、完整 resolved config、源码身份、先验、策略哈希和三类种子均记录。普通运行须有当时有效的来源/验证凭据和显式 --execute。

原地图的 K=4 候选等逻辑保持不动。新地图的“12 条原始路线压到 4 条”属于额外计算机制，不能声称与原基线计算量相同。完整报告每步规划 P50/P95、CPU 时间、查询次数、缓存命中、内存与超时回退；再用相同池/相同查询预算的强对照隔离研究机制。

## 6. 指标和统计口径

| 指标层次 | 统一记录 |
| --- | --- |
| 地图搜索主要指标 | Found 比例；found_penalized_steps 的场景均值，未发现记 max_steps=400；同时保留实际 found_step |
| 整体任务主要指标 | 任务成功率、碰撞率、发现前碰撞、超时；失败不得删掉后只比较成功时间 |
| 时间与回报 | 成功步数及失败截断口径、gamma=.95 团队回报、发现到交接/成功时间；奖励高低不替代任务指标 |
| 执行控制 | 接触后完成率、保持中断、Hold、停滞、换路与恢复失败；条件比例同时报告分母 |
| 模型机制 | 后验 ESS/模式/退化、预测质量、原池最优值损失、压缩半径、独立复核误差、ETA/横向误差 |
| 计算成本 | 原生环境步、目标预测步、路径查询、规划延迟、训练与评估墙钟、回退频率 |

found_penalized_steps 沿用当前 evaluation_records.py 的定义，避免重定义后与旧报告混用。碰撞为任务失败/竞争终止，不能当作与发现无关的随机删失。

ZERO 比较以场景配对，RL 比较以训练 seed 为学习重复单位，同时保留相同场景的配对。分别报告每个 seed 的原始结果和跨 seed 汇总，可用 seed/场景分层 bootstrap 给出区间；不能把粒子、时间步、重复确定性评估或同一模型的 100 个场景冒充 100 个独立训练重复。

每个 RL 架构可报告地图-RL 交互诊断：

    (NEW_RL - NEW_ZERO) - (OLD_RL - OLD_ZERO)

该量按指标分别计算，并保留不确定性及场景配对；不能仅凭一张训练回报图判定“新地图促进了 RL”。对 Found、成功率、碰撞与延迟的实际意义阈值，应在开发结束、查看测试结果前写入正式协议。目前尚无数据支持一个固定改善百分比，不能提前承诺。

## 7. 地图消融与实现欠项

六组主实验之外，先在 ZERO 条件下完成 PDF 要求的 MAP_NO_REPEAT、MAP_SPATIAL、MAP_SIMPLE_COMBINED、MAP_FILTER，以及去地图耦合、几何压缩、名义执行等模块对照。使用相同原始池/模型样本的机制比较应单独运行，不混成主闭环收益。只有零残差下机制成立，才有必要扩大 RL 条件下的消融。

本轮已补齐的原生地图主实验链路：

1. 在统一 Active 版本中提供 OLD/NEW 显式装配，旧图关闭研究分支，新图开启已冻结核心；原图、地图核心和来源证据分别保留。
2. Trainer、reference、evaluate 通过严格地图合同装配；B2/B3 的损失、奖励、网络、优化器及更新函数保持原实现。
3. 六组配置与计划生成区分地图/学习方法，固定逐回合训练任务、共同评估输入、独立初始化规则与预算；初始模型哈希成对核对。
4. 检查点绑定训练地图，原生评估强制 train_map=eval_map；不提供静默跨地图恢复。
5. 完成凭据、结果行、CSV 与统计保留地图/策略/来源，输出逐种子与场景配对结果、交叉 bootstrap 和学习曲线。
6. 开发与正式测试使用不同生成 seed；--exclude-run 复制并核对开发任务清单，按 ID、seed、物理指纹排除测试泄漏。
7. 原脚本版本的 112 项检查及 8 个限步回合通过：四个临时 RL 模型独立训练/原生评估，每模型最多 4 轮更新，未恢复模型文件。Linux 平台仍须新生成实机验收。

原生地图六组主实验已具备执行脚本，正式实验尚未执行。上述消融组、冻结策略跨地图诊断及后续 RL 研究仍有欠项；不能将脚本就绪或短程机制验证表述为性能提升或完整 PDF 全部交付。
