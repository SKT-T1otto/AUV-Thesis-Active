# R123：任务推进修复与独立消融

本次依据 pilot 失败审计，只修改路径选项的执行机制，入口为 `tools.r123_experiment`。原有路径注意力、事件预测头及其损失不增加新模块；旧训练器、地图、奖励、环境和历史权重保持原文件。本版本有独立源码身份，旧权重不能直接改标签后使用。

## 证据与改动

旧 A/B/C 最后开发评估各 12 回合，成功均为 0；发现数分别为 3/2/2，发现后的交接存在，但均未接触捕获。A/B 终止年龄 10 的频繁重提交、低速探测动作及恢复任务未完成是主要证据。C 虽减少切换，也没有解决低速动作。它们不足以证明地图是首要问题，也不能证明下面的改动必然改善成功率。

| 项目 | 本次行为 | 要解决的问题 |
|---|---|---|
| R1 | 每个候选路径有自己的动作库：路径跟踪基准，加六个单轴 ±0.15 归一化加速度残差；普通导航屏蔽旧自由探测动作 | 选了任务却执行无关路径动作，频繁刹车或小幅探测而不前进 |
| R2 | Full 移除学习型 β 的执行与训练梯度，用到达、路径失效、无进展触发重新选择；进展计时属于任务，不因重提交重置 | 最短年龄一到就结束选项，反复开始同一任务 |
| R3 | 原任务与恢复端点分开；到达恢复端点后回原任务；每个任务最多两次恢复，单段连续恢复总预算 150 步（30 秒） | 恢复成为永久主任务，覆盖搜索、等待或拦截 |

R1 保留原安全检查、验证过的缓冲区退出以及无有效动作时的刹车兜底。普通基准/残差存在有效动作时，刹车不与导航竞争。16 个动作槽位和网络参数尺寸保留，屏蔽重复槽位及探测槽位；原环境动作仍为 3D 加速度。相同状态下相同动作的安全检查只算一次，缓存仅在本次动作库构造内有效。

搜索任务到达或恢复耗尽，明确请求原 D2 重分配；收到有效的新任务才接续，期间等待刹车，不伪造完成。执行器拦截任务耗尽恢复预算后仍保留同一移动目标任务身份；公开路径可达时只跟踪根任务，不重新生成恢复预算。发现后搜索器冻结、交接后执行器转向公开移动目标的优先级高于任何恢复。捕获接触、连续保持、任务成功仍完全由原环境判定。

共同修复包括：D2 更新后失效的候选缓存清除；到达判断使用公开自由位置、间隙与速度条件；保存实际选择路径对应的动作与回放。它们在四组中相同，因此四组差分不能单独归因这些共同修复。网络时间注意力/路径注意力、事件递推、团队奖励、gamma=0.95、优化器、批量和更新频率保持旧设置。没有新增奖励项。

## 消融和停止规则

| 训练组 | R1 | R2 | R3 | 比较目的 |
|---|---|---|---|---|
| full | 开 | 开 | 开 | 完整改进 |
| no_r1 | 关 | 开 | 开 | 撤回 R1，恢复共享动作库和探测动作 |
| no_r2 | 开 | 关 | 开 | 撤回 R2，恢复学习型 β 与原局部进展计时 |
| no_r3 | 开 | 开 | 关 | 撤回 R3，恢复旧恢复生命周期 |

另有不训练的 rule 参考，使用相同 R123 动作、安全和生命周期规则。四组网络参数量、相同种子的初始权重相同；R2 组保留未训练的 β 参数以控制容量。Full − no_r* 是在其余两项开启条件下的条件作用，不能解释为独立主效应或交互效应。主消融不同时改地图或注意力。

1. Linux 源码验证：合成检查 + 四组各最多 32 个物理步、零原生训练更新。短检查不能作为完整任务成功证据。
2. rule 完整开发集：6 回合、每回合最多 400 步。至少 3 个成功且无碰撞才允许学习试验。未通过则先查任务流程或撤回机制，不继续扩大训练。
3. Full 筛查：仅一个从零训练模型，种子 20261115；最多 20 个训练回合且最多 8,000 个训练物理步。开头和结尾各评估同一开发集 6 回合（共 12 回合，最多另 4,800 步）。成功率较未训练策略提高且碰撞率不增加，才允许消融。
4. 条件消融：4 组 × 3 种子 = 12 个从零训练模型；每个 20,000 个训练物理步（总 240,000），仍各有前后 12 个开发评估回合。每条命令只启动一个指定组/种子，不自动连跑矩阵。筛查模型不混入这 12 个同预算模型。
5. 冻结设置后才显式运行独立 test（24 个场景）；每个冻结最终模型各评估同一组场景，不能用 test 选超参或最佳权重。最终权重固定为预算结束版本，不挑最佳检查点。仅有初末两次评估，不能宣称收敛。

训练集 32 / 开发集 6 / 测试集 24，场景与物理指纹均互斥。场景种子分别为 991001/992001/993001。训练采用固定循环场景次序，所有组保持一致；环境随机种子为训练种子加回合号。开发评估统一场景、统一环境与采样种子，恢复所有训练随机状态，不更新策略、评论家、目标网络、优化器或回放。

报告同时输出成功、碰撞、超时、发现、交接、捕获接触/保持、任务释放、恢复返回、恢复次数/步数、停滞、位移、跟踪误差、动作探测比例与耗时。主比较按种子配对，保留逐场景原始轨迹。3 个种子和 6 个开发场景只支持初步归因，不是正式性能验收。负面差分应促使撤回对应机制，不再默认增加模块。

完整任务成本仍可能较高；rule 参考最多 2,400 步，Full 筛查含开发评估最多 12,800 步，消融含开发评估最多 297,600 步。任何命令缺少 `--execute` 都仅预览。未通过门槛不会偷偷启动其他组。

## Linux 命令

以下脚本只验证、准备和跑 rule 开发参考，不启动训练。输出目录必须全新。

```bash
conda activate AUV
cd ~/AUV-Thesis/AUV-Thesis-11.12
git pull --ff-only
bash scripts/r123_linux_check.sh
```

脚本结束会打印本次 `ROOT`、`VALIDATION` 和 `REFERENCE`。门槛通过后，替换为打印的实际路径再手动启动唯一的 Full 筛查：

```bash
python -B -m tools.r123_experiment run \
  --root "$ROOT" --validation "$VALIDATION" --reference "$REFERENCE" \
  --arm full --seed 20261115 --execute
```

只有筛查通过才准备后续消融，数据种子/设置保持一致，四组逐一手动运行：

```bash
ATTR="work/collision_terminal/r123_attribution_$(date +%Y%m%d_%H%M%S)"
python -B -m tools.r123_experiment prepare --stage attribution --output "$ATTR" --execute
SCREEN="$ROOT/jobs/full_seed20261115/completed.json"
# 单次只选一个 arm 和 seed；其余组不自动排队。
python -B -m tools.r123_experiment run --root "$ATTR" \
  --validation "$VALIDATION" --reference "$REFERENCE" --screen "$SCREEN" \
  --arm no_r1 --seed 20261115 --execute
python -B -m tools.r123_experiment report --root "$ATTR" \
  --output "${ATTR}_report" --execute
```

独立测试例子（冻结设置后执行，不属于筛查或自动验证）：

```bash
python -B -m tools.r123_experiment evaluate --root "$ATTR" \
  --validation "$VALIDATION" --mode learned \
  --policy "$ATTR/jobs/full_seed20261115/policy_final.pt" \
  --suite test --final-test --output "${ATTR}_full_seed20261115_test" --execute
```

本地 Windows 机制检查不能替代实际 Linux 准入，也不能据此断言成功率改善。环境初始化和步数在验证收据中单独记账，历史结果与旧权重均不覆盖。
