# 路径进度与前馈语义修正

本版本修正原始轨迹明确暴露的两处执行接口问题，不增加脱困、注意力、奖励或训练模块。父版本为 governed，提交 b057577ba7e9b7d9ae86cb45c7527f472d409aa1；旧实现、清单、历史结果保持原字节。实现位于 chapter3_bser/r123_tracking，入口 tools.r123_tracking_experiment。四组全部关闭主动恢复；不改变任务、发现、交接、捕获、奖励、物理和安全阈值。

## 两项修正

路径衔接：同一个有效任务/阶段重新查询路径时，仅当新路径的前缀全部是旧路径已经完成的节点、后续仍包含旧跟踪节点，并且当前公开几何允许从真实位置直接连接该节点，才沿用进度。新障碍要求的绕行、新任务、不可达路径、冻结状态不继承。每步仍通过原有安全动作库检查，不改变占据地图，不放宽到达半径。记录 route_continuity_events。

前馈语义：固定中间节点的期望速度为零；只有 phase2、路线可达、已处最后节点且节点与移动任务端点一致时，才使用公开交接后的目标速度。原有速度治理、真实加速度限制、六个±.15残差、几何/制动备份检查、紧急刹车和已验证缓冲区退出不变。诊断新增 tracking_velocity。

## 主动恢复是什么

主动恢复是 R123 研究实现中的有界临时绕行分支：停滞/失效时从替代端点中选择临时目标，以 RECOVER 模式执行，真正到达后返回根任务；每个任务最多两次尝试、总计150步预算。它是在此前 path-option/ReachAvoid 已有替代端点思路基础上的任务生命周期机制，不是这次 tracking 修正新增的东西；也不是原始 D2 规则控制的必需组件。

11月16日对照中，修复后保留恢复进入11次，恢复端点到达和返回均为0；保留/关闭恢复两组都成功2/6，没有救回失败场景。一次成功场景早15步，不能说所有指标都更差；但没有证据支持它作为默认分支，且增加了路径查询与执行成本。因此关闭主动端点选择，先修执行接口。关闭的是替代任务分支，不是安全避障、刹车、缓冲区退出或原任务重查。以后若无独立任务收益，可继续删除，而不是不断加模块来补救它。

报告要求三组均完成，输出各场成功/发现/碰撞/超时/步数、静止/低速/刹车、交接/捕获接触，以及相对baseline的配对差值和两修正交互项。无发现的 found_step、无捕获记录的距离等保持null；汇总只对实际记录值取均值并记录样本数。旧轨迹没有 tracking_velocity，相关计数保持未知，不能伪造为零。

机制通过不代表完整任务效果提高；六个开发场景也不是正式泛化验收。先看完整成功率与各场失败阶段，再看低速计数。若修正无收益或有副作用，可以停用该修正。

## Linux 操作

更新项目后准备新目录（不要预先 mkdir BASE）：

```bash
conda activate AUV
cd ~/AUV-Thesis/AUV-Thesis-R123
git pull --ff-only
OLD=work/collision_terminal/r123_governed_20261116_215327_3078331
BASE="work/collision_terminal/r123_tracking_$(date +%Y%m%d_%H%M%S)_$$"
bash scripts/r123_tracking_prepare_linux.sh "$OLD" "$BASE"
```

准备成功后，可先手动运行两项都修的6场景；以下命令本身是规则评估，不训练、不加载模型：

```bash
python -B -m tools.r123_tracking_experiment evaluate \
  --root "$BASE/plan" --validation "$BASE/validation/validation.json" \
  --arm both --output "$BASE/both" --execute
```

另外两组分别启动，互不自动追加任务：

```bash
python -B -m tools.r123_tracking_experiment evaluate \
  --root "$BASE/plan" --validation "$BASE/validation/validation.json" \
  --arm path_only --output "$BASE/path_only" --execute
python -B -m tools.r123_tracking_experiment evaluate \
  --root "$BASE/plan" --validation "$BASE/validation/validation.json" \
  --arm feedforward_only --output "$BASE/feedforward_only" --execute
```

进度与汇总：

```bash
python -B -m tools.r123_tracking_experiment status \
  --root "$BASE/plan" --results "$BASE" --execute
python -B -m tools.r123_tracking_experiment report \
  --root "$BASE/plan" --results "$BASE" --output "$BASE/report" --execute
```

最终文件为 `$BASE/report/report.json`。三个新组各有 completed.json 才能汇总；不要靠日志停止打印判断。新终端需先恢复 BASE，例如用真实目录执行 `source work/collision_terminal/r123_tracking_实际时间与编号/session.env`。
