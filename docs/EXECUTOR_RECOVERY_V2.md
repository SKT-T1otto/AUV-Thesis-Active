# 老地图执行器移动、驻留与恢复 v2

本版先只处理 OLD 地图下的搜索期待命控制，保留原 D2、原 v1 保护及其证据。v2 是独立标识的导航策略和运行时残差门控修改，不是数值等价的地图加速。`NEW` 条件与 v2 的组合会被拒绝，待老地图验证后再单独接回新地图。

## 为什么加入执行器独立设置

已完成的 Linux 开关对照中，OLD_ZERO 原版有两场搜索期执行器撞障碍；v1 开启后，一场失败转到拦截期，另有一场新增执行器搜索期碰撞。ZERO 没有学习残差，说明奖励、噪声或学习率调整本身无法修复底层移动/驻留问题。

新增 `executor_search_residual`，默认 `disabled`：

- B2/B3 搜索期，执行器的**归一化学习残差**被现有执行掩码置零，导航先验和正常物理动力学继续运行。该设置不会把位置或速度锁死，也不会将执行器标记为 `agent_finished`。
- 回放保存实际应用的零残差和关闭的当前/下一状态掩码。搜索样本不更新执行器 actor；critic 仍按原方法学习。发现目标后恢复原门控，原学习残差可继续作用。
- 其他三个搜索器、28D/3D/124D、gamma=.95、奖励、网络、优化器、更新计划、目标运动、发现、交接和终止规则保持原文件行为。
- `original` 保留原残差，供后续单独消融使用；本轮 ZERO 试验不能说明它在 B2/B3 中更好。预测使用公开运动误差估计，不提供对任意学习残差的安全保证。

本轮不增加执行器专用碰撞奖励、不调整奖励权重、不增加网络输入维度；这些是需要独立训练与对照的后续算法实验。

## 移动、驻留与恢复

1. **当前公开地图与端点一致。** 必要求路时构建只读的当前公开快照，显式使用当前执行器连续位置及语义待命目标作端点；不修改原 D2 provider、控制器缓存、待命分配或刷新周期。失败查询默认间隔 5 个物理步，目标变化可以提前触发，每次编译最多一次查询。
2. **优先保留可验证的原指令，只沿公开已判空闲区域运动。** 先检查原 D2 当前跟踪目标，验证通过就保留其航点和跟踪阈值。被拒绝时才改为 0.9 米、0.45 米、0.225 米的局部目标，不全局降低移动速度。名义跟踪最多 8 步，再朝固定制动锚点预测 16 步；检查整段运动、已知障碍余量和未知体素。未知体素检测只枚举短线段包围盒中的相邻体素，并与独立的全体素求交 oracle 对照。
3. **公开扰动估计。** 从上一条已安装导航意图及公开速度变化估计外部速度增量，使用最多 8 个样本；不读取真实流场参数或真实障碍列表。估计排除明显速度饱和样本并限幅。预测仍有模型误差，不能视作数学安全保证。
4. **固定锚点驻留。** HOLD/RECOVER 中保留锚点，不随当前位置逐步漂移。锚点失效时，从当前点、公开障碍外侧、反速度方向、最近安全点和侧向点中检查最多 7 个候选。若已在规划膨胀余量内，只允许原始公开占据几何之外、不继续缩小余量且最终增加余量的恢复。
5. **恢复后再出发。** 恢复至少保持 3 步，有连续两次可验证移动意图且速度低于 0.25 才恢复 MOVE。所有候选失败时保留固定制动意图并明确标记 UNVERIFIED，不隐藏终止、不清零物理速度、不把未验证操作标成安全。
6. **发现目标后的边界。** 本轮保留原拦截控制，记录 HANDOFF_EXIT。报告同时统计搜索期和全部阶段执行器碰撞，防止把失败推迟/转到拦截期当作修复成功。原搜索器直接指令不由新增桥接层改写，但执行器轨迹会通过原联合分配目标间接影响后续规划。

公开占据分类、有限观测、初始无可行安全状态以及模型误差仍可能导致失败。遇到长时间 UNVERIFIED 或驻留不动，必须报告并继续定位，不能通过改变碰撞定义、提前结束或增加允许碰撞次数来通过检查。

本轮 8 次环境初始化预算已经用完，没有自动追加环境运行。修订版由当前完整回归、公开几何 oracle 和实际 B2/B3 掩码/更新测试验证；早期环境检查只用于相同接口、扰动估计、驻留/恢复接线的证据，不冒充修订版的环境结果。当前版本是否仍有0012退化，以及是否能避免原82/96步执行器碰撞，必须由下面的实际 Linux 当前源码验证和完整400步对照回答。**本版是待验证的研究修补，尚不能宣称闭环已经稳定。**

## 本轮实验

`cli executor-experiment` 使用 `configs/executor_recovery_pilot_v2.json` 准备两组，均为 OLD_ZERO：

| 目录 | 地图 | 执行器控制 | 学习 |
|---|---|---|---|
| baseline | 原 D2 老地图 | 原版无新增保护 | 无 |
| recovery | 原 D2 老地图 | v2 移动/固定驻留/恢复 | 无 |

相同 12 个开发场景、相同顺序及创新种子、每场最多 400 步，共 24 次评估，零训练作业。生成种子沿用 827699，重点追踪 0002、0006、0011、0012；它们已经用于定位问题，不是独立验收集。规格中的 `new_map_config` 仅为兼容原计划格式的未使用字段，运行时 `research_config=None`，不创建新地图信念会话。

报告：

- `executor_episodes.csv`：逐场发现/成功/终止、碰撞对象和阶段、MOVE/HOLD/RECOVER/UNVERIFIED 次数、查询/修复次数及编译时间。
- `paired_deltas.csv`：执行器搜索期、执行器全部阶段、全队碰撞、发现、成功五类配对差值。
- `baseline/groups.csv` 与 `recovery/groups.csv`：任务指标与运行时间。
- 原生 `episodes.jsonl` 的 `planner.executor_recovery.trace`：最多 64 条公开控制尾部轨迹、固定锚点、扰动估计、预测拒绝原因和路线查询失败原因。

首先要求原来的搜索期碰撞不是简单延后、0011不新增执行器碰撞、全部阶段碰撞不增加，同时检查发现率、成功率及长期驻留。机制检查不等于完成该要求，必须看完整 400 步结果。B2/B3 只在这一步通过后做新身份训练，再比较独立残差设置；不加载旧权重充当新实验。

## Linux

继续使用现有目录和 AUV 环境。先将 `REV` 设为本次发布的完整提交号并 fetch/checkout，确认工作区干净。以下路径均为新目录：

```bash
export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 PYTHONUNBUFFERED=1
STAMP="$(date +%Y%m%d_%H%M%S)_$$"
CHECK_EXEC="$PWD/work/executor_recovery_checkout_$STAMP"
RUN_EXEC="$PWD/work/collision_terminal/executor_recovery_$STAMP"
REPORT_EXEC="$PWD/work/executor_recovery_report_$STAMP"

python -m tools.validate_checkout --output "$CHECK_EXEC" \
  --require-linux --expected-commit "$REV" --execute &&
python -m cli executor-experiment prepare --root "$RUN_EXEC" --execute &&
python -m cli executor-experiment run --root "$RUN_EXEC" \
  --validation "$CHECK_EXEC/validation.json" --execute &&
python -m cli executor-experiment report --root "$RUN_EXEC" \
  --output "$REPORT_EXEC" --execute

cat "$REPORT_EXEC/paired_deltas.csv"
cat "$REPORT_EXEC/executor_episodes.csv"
```

Linux 验证为全部回归和 8 次 OLD-only、每次不超过 32 步的 ZERO 接线检查，无环境训练、无 checkpoint 文件恢复。短程检查不能覆盖原第82/96步的碰撞；后面的400步人工实验承担长程验证。

父版本源码/文档归档约 1.6 MiB。已发布的来源和证据文件通过精确哈希引用保持不可变，不再次嵌套归档，不包含训练权重或用户结果目录。
