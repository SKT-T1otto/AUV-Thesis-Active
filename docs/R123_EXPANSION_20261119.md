# R123 新增24场的配对扩展验证

冻结tracking both与当前task_sync控制代码，新增24个M20_MOVING_UNKNOWN_MULTI场景。旧六场保留为开发回归记录，新增24场单独报告，不把反复调过的旧六场混成独立测试集。此轮仍是扩大开发筛查，不是最终论文泛化验收。

## 固定设计

- 沿用原场景生成器和可行性检查，四组固定种子2026111901、2026112901、2026113901、2026114901，各生成6场。全部接收，不按任务结果重采样。
- 新场景、原配置、原选项和旧清单排除指纹冻结在configs/r123_expansion_v1；与旧训练/开发/测试输入进行物理指纹去重。旧测试只读取指纹进行排除，不读取结果或选择模型。
- 两组均使用tracking both，只有task_sync开关不同。两组统一使用已存在的只读FailureObserver，不改变控制算法。相同场景使用相同环境种子20261119+index；逐场交替两组先后顺序。
- 24场×2组×最多400步，Linux完整评估上限19,200个新增物理步。两组均需新跑，不能导入旧六场充当新场景基线。规则控制、不训练、不加载权重，保留原奖励、任务判据、目标运动、动力学和安全阈值。
- Windows本地新入口验证最多4次初始化×32步=128步，分别比较父tracking与带观察器的关闭同步版本、原同步与带观察器的开启同步版本，要求完整物理/决策trace一致。Linux复用同一控制源码既有的59项检查和128步原生验证收据，只新增工具的零步合成检查。

场景只按原生成分布抽样，初始距离、目标速度/方向、障碍数等分布在准备报告中描述，不人为按好坏结果平衡。24场能降低对旧六场的依赖，但仍不足以代替独立测试集和学习算法的多训练种子评估。

## 运行与证据

新入口位于tools/r123_expansion.py；其独立清单为provenance/r123_expansion_manifest_v1.json。旧控制清单、旧结果和历史权重保持原字节。所有命令默认dry run，只有显式--execute才执行。

将本轮列明的新文件同步到Linux项目后，在原AUV环境手动运行：

```bash
conda activate AUV
cd ~/AUV-Thesis/AUV-Thesis-R123
(
  set -euo pipefail
  VALIDATED=work/collision_terminal/r123_task_sync_20261118_223936_3078331
  BASE="work/collision_terminal/r123_expansion_$(date +%Y%m%d_%H%M%S)_$$"
  bash scripts/r123_expansion_linux.sh "$VALIDATED" "$BASE"
)
```

脚本不会连接Linux或自动执行git操作。它只读取冻结清单，依次prepare、零环境check、48个限步回合、report。每25步打印进度，每个回合完成后写独立completed与哈希，全部完成后输出ALL 24 PAIRED EXPANSION SCENES COMPLETED。碰撞、漏搜或超时都按原任务正常记为结果并继续；只有接口、数据、源码或执行错误停止。没有自动重试、追加回合或训练。

输出目录必须全新，已有文件不覆盖。中断或异常时保留已完成回合与failed.json中的消耗，不自动从头重跑。再次运行需先核对未完成回合和已经消耗的预算。

## 统一报告口径

报告必须取得24个完整配对，验证所有输出哈希及场景/组别/种子；从原始轨迹重算指标、首次扫掠发现、接触与原5区间连续保持。逐场保留发现、交接、成功、碰撞、低速、制动、等待、任务完成及紧急部署。

首要比较为成功数和配对获救/丢失数；发现数不能替代成功数。搜索低速、制动和等待同时给相同搜索时间窗的结果，避免发现早晚造成分母差异。报告提供描述性的Wilson区间，但不会自动宣称统计稳健性、正式性能通过或授予训练准入。

墙钟时间包含观察器工作量，且总执行步随终止时间变化，保留为成本诊断，不直接宣称算法加速。生成清单、工具检查、原始回合、每回合完成收据、总完成记录和配对报告全部保留。本轮准备过程没有执行19,200步的Linux批次。
