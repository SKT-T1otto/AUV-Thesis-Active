# 第三章 R123 捕获末段连接对照

Windows 短回合验证完成。两组采用相同的任务同步、规则控制和原捕获判据。实验组只在已交接的执行器距已承诺端点不超过一个水平栅格时，尝试将当前跟踪点设为这条路线的末节点。在本批地图上，一个水平栅格为 2 米。正式场景 0013、0017 的捕获结果由 Linux 完整配对评估给出。

## 行为改动

- 原路径查询须返回可达的普通根任务路径，末节点须匹配任务与端点。等待、已释放任务、恢复路径和专用起点退出连接保留原路线。直连每步都要通过当前公开占据栅格的整段检查和原有的扫描几何检查。
- 直接跟踪末点只影响当步的执行游标。下一步推进常规游标以及每次重新查询前，都恢复真实栅格进度。新地图否决直连时，执行器可以立即回到尚未走过的路点。原查询路径 ID、全部路点和查询时的预计成本仍代表原始网格路线。逐捕获动作记录同时给出普通游标和实际游标。
- 末节点沿用已有的目标速度前馈、限速、动作掩码、制动备份和缓冲区退出。任务更新仍由已有的公开端点更新机制触发。捕获使用原环境的三维 0.8 米半径和连续 5 个完整物理区间保持。候选端点使用当时已经承诺的公开坐标，真实目标轨迹仅用于离线计算指标。
- 对照提交为 `98630ea98d90701ad497ebd92336b11cb04c02bd`。新增实验身份为 `cc1f46cbeef44280fc9512bb47530461e830d713b311500577e2f8fc72e4a948`。原版同步入口继续使用原实现。

|---|---|---:|---:|
| focus | 扩场 0013、0017 | 每场各跑同步栅格与同步直连一次，共 4 回合 | 1,600 |
| regression | 扩场 0001、0006、0007、0010、0011、0015、0021、0022；旧六场中的 0001、0003、0004、0005 | 每场只跑直连，共 12 回合，使用已有同步栅格原始轨迹作对照 | 4,800 |

每组沿用历史场景、初始状态、种子、400 步上限和相同的规则控制。扩场编号使用 `r123_expand_20261119_` 前缀，旧六场使用 `po_eval_992001_` 前缀。回归中有 11 个同步版原成功场，另有一个旧六场 0004，在 tracking 曾成功、同步栅格已失败，单独检查能否恢复。

focus 先将新跑的栅格控制组与原同步轨迹逐步核对。两个阶段都核对首次采用直连前四台智能体的动作与物理轨迹，以及两组发现、交接的时刻。对于全程未启用直连的场景，核对整个回合。每场输出完整新轨迹与配对指标，阶段报告列出新增成功和丢失成功。首次接触按扫掠距离计，最终成功按连续完整区间计。墙钟耗时按实际记录，包括观察器与机器环境开销。

在 Linux 项目下用新建的同一个 `RUN` 目录依次调用 `bash scripts/r123_final_leg_linux.sh focus "$RUN"` 和 `bash scripts/r123_final_leg_linux.sh regression "$RUN"`。默认从 `work/collision_terminal` 读取历史扩场、任务同步和任务同步回归三个结果目录。若已迁移，可给脚本附加一个或多个 `--history-root 目录` 指定这些运行目录的父级。程序按原始完成收据校验输入，每 25 步输出进度，回归完成后把两阶段结果打包为 `$RUN.tar.gz`。
