# R123 规则修正与删除对照

本版本先检验任务生命周期，入口为 `tools.r123_rule_experiment`；没有训练子命令，不加载权重。旧 R123、旧清单及旧结果保留原字节，不用新标签重解释旧结果。新实现位于 `chapter3_bser/r123_repair`，只继承旧执行器的奖励、物理、成功判据、R1动作构造及安全检查，没有新增神经网络或奖励。

## 三组与改动

| variant | 执行内容 |
|---|---|
| legacy | 冻结的旧规则实现；推荐直接导入用户已完成的六回合结果，避免重跑 |
| repaired | 下述公共修正，保留有界的主动恢复端点选择 |
| no_recovery | 相同公共修正，删除主动恢复端点生成/查询/选择，不进入 RECOVER |

公共修正：真实恢复尝试有自己的进展计时；根任务身份、次数及150步总预算保留，重复提交同一尝试不能续期。真正到达恢复端点才记录 RECOVERY_RETURN；失败后选择根任务则记录 ROOT_FALLBACK，并继续根路径，不伪造到达或立即开启新绕行。耗尽预算也可在公开路线可达时恢复根任务跟踪，不通过同一旧停滞状态反复释放/恢复。

任务来自真实 D2 allocation 的 candidate_id 和 waypoint。UNASSIGNED/hold 的当前位置占位不能成为完成的新搜索任务。发现后 phase3 同时冻结动作与任务记账，不再产生恢复、结束或重提交事件。轨迹增加 assignment_kind 和 assignment_token。

D2重分配继续使用原候选池和目标函数，但按请求搜索器逐个进行原子提案，避免一人无候选拒绝其他人的请求。无有效起点时，最多查4个、3米内公开已知空闲且规划图有效的中心；仅当公开观测几何验证直线段通过才执行物理起点连接。绝不移动虚拟规划位置或把障碍单元改为空闲。每一步仍经过原安全动作检查；无连接时仅保留已验证的原缓冲区退出，否则刹车待命。连接不是新搜索任务，也不计主动恢复，所有组都有相同规则。无公开安全路线时仍可能等待，不能承诺消除所有超时。

repaired − no_recovery 只比较公共修正条件下主动恢复端点分支的作用。两者与 legacy 的差异包含整个修正包，不能宣称分辨了每项公共修正对成功率的独立贡献。组合检查分别复现并约束具体缺陷；完整回合的因果效果仍以Linux规则对照为准。若删除恢复更好，应删除分支，而不是默认增加模块。

## 数量和停止规则

- 验证：旧回归加新组合检查；显式原生短检查5次环境初始化，每次最多32步，共最多160步，零原生训练更新。三组各一次普通检查，修复两组各一次内部任务释放检查（仅控制器状态注入，不改环境奖励或成功判据）。
- 准备：直接复用原六个 development 场景、配置和选项，不重新生成训练集和测试集。新源码、新清单、新验证收据、全新输出目录；旧验证收据不能使用。
- 完整评估：repaired 和 no_recovery 各6回合，每回合最多400步，各最多2400步；每条命令只跑指定的一组。旧六回合作为历史参考导入，默认不再跑legacy。因此本轮新增上限为160+4800=4960物理步，不含任何训练。
- 不自动启动Full筛查或12模型矩阵，不降低原规则门槛。报告不授予训练准入；选择删除/保留恢复后，再冻结后续训练设置。六个场景不能证明收敛或正式论文性能。

新增组合检查包括：旧停滞→首次恢复→下一步；两次真实失败→释放；同尝试重复提交；恢复持续进展但总预算到期；恢复返回根任务；一个搜索器无候选不阻止另一个；未分配占位；发现后冻结；等待中公开起点连接与原安全退出；去恢复控制没有候选端点和RECOVERY_ENTER。

## Linux 操作

更新后先准备，不使用旧的 `launch.sh`：

```bash
conda activate AUV
cd ~/AUV-Thesis/AUV-Thesis-R123
git pull --ff-only
OLD=work/collision_terminal/r123_20261116_103339_2030716
BASE="work/collision_terminal/r123_rule_repair_$(date +%Y%m%d_%H%M%S)_$$"
bash scripts/r123_rule_prepare_linux.sh "$OLD" "$BASE"
```

准备成功后，先运行去恢复组（6回合，最多2400步）：

```bash
python -B -m tools.r123_rule_experiment evaluate \
  --root "$BASE/plan" --validation "$BASE/validation/validation.json" \
  --variant no_recovery --output "$BASE/no_recovery" --execute
```

再单独运行修复组（另外6回合，最多2400步）：

```bash
python -B -m tools.r123_rule_experiment evaluate \
  --root "$BASE/plan" --validation "$BASE/validation/validation.json" \
  --variant repaired --output "$BASE/repaired" --execute
python -B -m tools.r123_rule_experiment report --root "$BASE/plan" \
  --results "$BASE/no_recovery" "$BASE/repaired" \
  --output "$BASE/report" --execute
```

每一步均不覆盖已有输出；错误立即停止。新终端需重新设置同一个 BASE 路径。报告输出逐场景配对差分，以及成功、碰撞、发现、超时、等待、恢复、连接和冻结记账等证据。保留完整 episodes.jsonl，不凭总奖励判断流程修复是否有效。
